# Skill Evolution — авто-покращення скілів

Скіли еволюціонують з досвідом. Не "після сесії" — а в конкретні моменти.

---

## 1. Коли ТОЧНО спрацьовує evolution

Не "після сесії" (агент не знає коли сесія закінчується). А в ці конкретні моменти:

### Тригер A: Юзер каже завершальне
Слова: "все", "готово", "на сьогодні", "дякую", "на гіт", "пуш"
→ Перед останнім push: skill review (30 секунд, не окремий крок)

### Тригер B: Завершено значний блок роботи
Ознаки: 3+ файлів змінено, або 1+ година роботи, або задача закрита
→ Одразу після commit: чи скіл допоміг? Чи щось треба додати?

### Тригер C: Скіл не спрацював
Ознаки: агент працював "поза скілом", імпровізував, шукав рішення не покрите правилами
→ НЕГАЙНО: записати в USAGE_LOG як ❌, визначити чого бракує

### Тригер D: Юзер виправив агента
Ознаки: "не так", "стоп", "роби інакше"
→ Перевірити: чи це скіл-проблема чи rule-проблема? Оновити відповідний файл

### Тригер E: Новий інструмент або версія
Ознаки: `npm update`, новий MCP, зміна стеку
→ Перевірити всі скіли де цей інструмент згадується

---

## 2. Що КОНКРЕТНО робити (skill review = 30 секунд)

Не витрачати окремий крок. Вбудувати в природний flow:

```
Завершив задачу → commit → [SKILL REVIEW]:
1. Який скіл використовувався? → +1 рядок в USAGE_LOG
2. Чи довелось імпровізувати? → якщо так, додати правило в SKILL.md
3. Чи з'явився новий anti-pattern? → якщо так, додати в ЗАБОРОНЕНО
→ Якщо були зміни в скілі → commit разом з основною роботою
```

НЕ робити:
- Окремий "skill evolution step" (це waste)
- Повний аудит всіх 19 скілів (це brain-maintenance, не evolution)
- Запитувати юзера "чи мені оновити скіл?" (просто зроби)

---

## 3. Skill Usage Log

`skills/USAGE_LOG.md` — оновлювати під час commit, не окремим кроком:

```markdown
| Дата | Скіл | Проєкт | ✅/❌ | Нотатки |
```

Правила:
- ❌ 2+ рази → терміновий rework
- 60+ днів без використання → review при brain-maintenance
- 5+ uses ✅ → скіл стабільний, не чіпати

---

## 4. Що НЕ еволюція скілів

- Зміна бізнес-логіки → проєктний CLAUDE.md
- Нове правило роботи → brain/rules/
- Нова knowledge → brain/knowledge/
- Еволюція = тільки зміна SKILL.md файлів (тригери, правила, приклади)
