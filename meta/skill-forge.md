# Skill Forge — Кузня нових скілів

Протокол створення нових скілів коли існуючий набір не покриває задачу.

---

## 1. Тригери створення

- Задача не покривається жодним існуючим скілом
- Повторюється патерн роботи (3+ разів схожа задача)
- Юзер явно просить "зроби скіл для X"
- Під час Skill Router (CLAUDE.md §3) — match = 0

---

## 2. Anti-Duplicate Check (обов'язково першим)

Перед створенням:
1. Прочитай `skills/README.md` — перевір всі 19+ скілів
2. Прочитай SKILL.md найближчих кандидатів — може достатньо розширити існуючий
3. Якщо новий функціонал логічно доповнює існуючий → НЕ створюй новий, а розшир існуючий

---

## 3. Протокол створення

### Крок 1: Аналіз
- Визнач роль (Role) — хто цей скіл?
- Визнач тригери — коли активується?
- Визнач constraints — що ЗАБОРОНЕНО?
- Визнач output — що має бути результатом?

### Крок 2: Структура файлів
```
skills/<slug>/
└── SKILL.md
```

### Крок 3: Формат SKILL.md
```yaml
---
name: <slug>
description: <Одне речення з точними словами-тригерами для активації>
metadata: {"tags": ["tag1", "tag2", ...]}
---
### ROLE: <Роль — хто ти коли цей скіл активний>
**Focus**: <Одне речення — на чому фокус>

### CONSTRAINTS & EXECUTION
- <Конкретні правила, заборони, патерни>
- <Інструменти, команди, фреймворки>

### OUTPUT EXPECTATIONS
<Що має бути результатом роботи>
```

### Крок 4: Validation
Згенеруй 20 тестових промптів:
- 10 що МАЮТЬ активувати скіл (true positives)
- 10 схожих що НЕ ПОВИННІ (false positives)
Перевір що description точно розділяє ці групи.

### Крок 5: Реєстрація
1. Додай рядок в `skills/README.md` у відповідну таблицю
2. Оновити таблицю маршрутизації в `CLAUDE.md` §3

### Крок 6: Commit
```
skills: add <name> — <короткий опис що вміє>
```

---

## 4. Правила якості

- **Constraints First** — у скілі важливіше що ЗАБОРОНЕНО, ніж що дозволено
- **Конкретність** — жодних загальних слів. Тільки конкретні інструменти, команди, патерни
- **200-500 рядків** max — решту виносити в `scripts/` або `docs/`
- **Живий документ** — скіл оновлюється коли змінюються best practices або інструменти

---

## 5. Коли НЕ створювати скіл

- Одноразова задача що не повториться
- Задача покривається комбінацією існуючих скілів
- Скіл був би занадто примітивним (< 20 рядків корисного контенту)
- Скіл дублює те що вже є в `brain/rules/`
