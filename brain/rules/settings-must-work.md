# Все, що є в налаштуваннях, МАЄ працювати

## Правило
Кожне поле в UI налаштувань зобовʼязане мати реальний enforcement у коді. Настройка без живого читача в продакшн-шляху — брехня юзеру і борг. Заборонено: додавати поле в UI/схему «на потім», лишати «декоративні» перемикачі, зберігати значення які ніщо не читає.

## Як застосовувати
1. Додаєш поле в налаштування → в ТОМУ Ж PR підключаєш його до реальної поведінки + тест.
2. При аудиті фічі: пройтись по полях відповідного табу і grep-ом підтвердити продакшн-читача для КОЖНОГО (не settings-service/UI, а місце, де значення реально змінює поведінку).
3. Знайшов мертве поле → або підключити, або видалити з UI (рішення юзера, якщо неочевидно).
4. Мертвий модуль-«читач», якого ніхто не викликає (як email-scheduler у одному проєкті) = поле теж мертве; коментарям «all X flows through here» не вірити — перевіряти викликами.

## Прецедент
проєкт 21.07.2026: `replyDelayMin/MaxMinutes` і бізнес-години були в UI, але єдиний читач (`sendOrSchedule`) не мав жодного продакшн-виклику — пауза відповіді клієнту «1-5 хв» не працювала взагалі. Юзер: «Звичайно, все що є в налаштуваннях має працювати».

## Сфера
**ВСІ проєкти.** Стосується нових фіч, аудитів, ревʼю.
