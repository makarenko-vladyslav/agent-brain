# Статусні питання = ТІЛЬКИ живі дані, ніколи з памʼяті

## Правило
Коли юзер питає «що по тасках», «що по проєкту», «який стан», «готовність до релізу» тощо — вся інформація має бути актуальною **на момент питання**. ЗАБОРОНЕНО відповідати з памʼяті, CLAUDE.md-аудитів чи попередніх сесій: ці зрізи застарівають за дні, а закриті/нові issues роблять відповідь брехнею.

## Як застосовувати
1. **Спершу живі джерела, потім відповідь:** `gh issue list` (+ `gh issue view` за потреби), `git log`/`git status`, стан проду (health/логи) — залежно від питання.
2. Памʼять і CLAUDE.md використовувати лише як **довідку для інтерпретації** (відсотки виконання, контекст задач) — і явно позначати, що це оцінка з дати X, якщо не перевірено кодом зараз.
3. Якщо живу перевірку неможливо виконати (нема мережі, юзер відхилив команду) — чесно сказати «це зріз з памʼяті від <дата>, не живі дані», а не подавати як актуальний стан.
4. Розбіжність памʼять ↔ живі дані = оновити памʼять одразу.

## Чому

## Сфера
**ВСІ проєкти, назавжди.** Стосується будь-яких статусних питань: таски, issues, стан проду, прогрес фіч, готовність до релізу.
