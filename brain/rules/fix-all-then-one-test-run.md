# Спершу всі фікси, потім ОДИН тестовий прогін

**Правило власника, 02.08.2026.** Стосується будь-якого генеративного пайплайну.

1. Зібрати всі знайдені дефекти і виправити їх **усі**.
2. Прогнати **один** екземпляр.
3. Перевірити самому, потім показати власнику.
4. Решту — лише після його підтвердження.

## Чому

02.08 у одному проєкті я перезапускав генерацію 5 сайтів після кожного окремого фіксу:
п'ять повних прогонів, ~$15 API за день, і власник кілька годин не бачив
жодного результату. Його слова: «я поки не мільйонер щоб після фіксу кожного
багу перезапускати весь пайп для 5 сайтів».

## Як застосовувати

Знайшов баг посеред пачки — **не** перезапускати пачку. Дописати в список,
довести всі фікси до кінця, перевірити на одному екземплярі. Пачка — це
фінальна демонстрація, а не інструмент налагодження.
