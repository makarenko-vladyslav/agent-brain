# Spline V2 — 3D-редактор, у який пускають Claude Code через MCP

> Локальний MCP-сервер у складі десктопного застосунку дає агенту працювати в живій сцені, лишаючи її редагованою; рушій переїхав на WebGPU. Альтернатива ручному three.js/TSL там, де потрібна швидкість, а не повний контроль.

## Що змінилось

**MCP-сервер.** Іде разом із десктопним застосунком, локальний. Відкриває редактор для Claude Code, Cursor, Codex, Antigravity, VS Code. Агент працює **всередині живого проєкту** — змінює сцену й поведінку, і результат лишається повністю редагованим руками. Це не експорт в один бік.

**Власний агент Spline.** Читає сцену, запускає інструменти самого редактора й **робить скріншоти, щоб перевіряти свою роботу по ходу** — той самий цикл, яким користується людина. Дістає до об'єктів, матеріалів, світла, камер, булевих операцій, частинок, клонерів, lathe, неба, змінних, і до інтерактивності через події та стани.

**Три режими:** Edit — канвас; Code — повноцінний редактор з підсвіткою, автодоповненням Spline API й автозбереженням; Preview — програє все разом, сцену з HTML/JS.

**Рушій на WebGPU** (WebGL як запасний): PBR-матеріали, HDR-освітлення, screen space reflections, нові системи неба й туману, пил, vertex colors, система волосся.

## Де це доречно, а де ні

**Доречно:** швидкий 3D для сайту клієнта, де сцена — прикраса, а не суть. Продуктові мокапи, інтерактивні об'єкти, hero-сцени. Виграш у годинах, і замовник може щось поправити сам.

**Не доречно там, де вже є adr сайт портфоліо 3d architecture.** Той проєкт свідомо стоїть на `three/webgpu` + TSL: TSL компілюється і в WGSL, і в GLSL, що дає адаптивні тіри якості й повний контроль над шейдерами — саме те, чого вимагає рівень Awwwards SOTD. Spline — чужий рушій і чужий формат сцени; міняти на нього означає віддати контроль заради швидкості. Для «іскри, що летить крізь вісім локацій» це поганий обмін.

**Практичний висновок:** тримати як інструмент для замовницьких сайтів і швидких сцен, не як заміну власному рушію.
