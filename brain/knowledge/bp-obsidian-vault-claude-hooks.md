# BP: Obsidian Vault як єдине джерело правди + Claude Code хуки-енфорсери
> Vault плюс три хуки Claude Code, що змушують читати доки перед роботою й оновлювати після. Переносний рецепт проти дрейфу документації.

**Дата:** 2026-06-19 · **Походження:** `github.com/textura-agency/next16-claude-starter` (адаптовано) · **Вперше застосовано:** `~/Projects/сайт-портфоліо/` (див. `adr-сайт-портфоліо-3d-architecture.md`)

## Навіщо
Документація дрейфує тієї ж миті, коли покладається на памʼять (мою чи юзера). Цей патерн робить так, що АІ-агент **читає доки ПЕРЕД роботою і оновлює їх ПІСЛЯ** — автоматично, без нагадувань. Цінність не в бойлерплейті, а в **системі змушування**.

## Три складові

### 1. Vault (`obsidian/`) — канонічний «мозок проєкту»
Папка markdown-нот зі звʼязками `wikilinks`, відкривається як Obsidian-vault. Структура (приклад):
- `README.md` — Map of Content (визначає весь граф wikilinks; пиши його ПЕРШИМ).
- Тематичні теки під РЕАЛЬНИЙ стек проєкту: `architecture/`, `engine/` (або `frontend/`), `design/`, `workflows/`, `meta/` (changelog + decisions-log/ADR), `templates/`.
- Кожна нота: YAML-frontmatter (`tags`, `updated`), Obsidian-callout-и (`> [!warning]`, `> [!tip]`), таблиці, `## Related` в кінці, ≤200 рядків.

### 2. Тонкі shim-и в корені
- `AGENTS.md` — hard rules + вказівник у vault (НЕ дублює контент).
- `CLAUDE.md` — лише `@AGENTS.md` (import).
- `.cursorrules` — дзеркало правил для Cursor (Cursor не розуміє `@import`).

### 3. `.claude/settings.json` — 3 хуки
- `SessionStart` → `additionalContext` вказує читати `obsidian/README.md` + гайд перед роботою.
- `UserPromptSubmit` → на кожен запит нагадує звіритись із потрібною нотою + оновити доки в тому ж ході.
- `Stop` → блокує завершення **один раз за turn**, щоб підтвердити що vault оновлено.

## Готові команди хуків (копіпейст)
SessionStart / UserPromptSubmit — той самий шаблон:
```
echo '{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"<текст без апострофів>"}}'
```
Stop — one-shot через `$TMPDIR`-маркер за `session_id` (гарантує МАКС 1 блок/turn, без нескінченного циклу):
```
M="${TMPDIR:-/tmp}/claude-vault-stop-$(jq -r .session_id 2>/dev/null)"; if [ -f "$M" ]; then rm -f "$M"; exit 0; fi; touch "$M"; echo '{"decision":"block","reason":"<нагадування оновити vault, без апострофів>"}'
```

## Підводні камені (вистраждані)
- **`.gitignore`:** якщо `.claude/` цілком ignored — хуки НЕ комітяться (не team-wide, зникають на іншому клоні/CI). Фікс: `.claude/*` + `!.claude/settings.json` (комітимо лише хуки, решта `.claude/` приватна).
- **`jq` обовʼязковий** для Stop-хука (читає `session_id` зі stdin). На macOS є `/usr/bin/jq`. Перевір `which jq`.
- **Без апострофів** у текстах хуків — вони всередині `echo '...'` (одинарні лапки зламаються). `don't` → `do not`.
- **НЕ копіювати чужий контент vault** — переноситься МЕХАНІЗМ, а контент пишеться під реальний стек (читати `package.json` + `src/`, документувати що Є, а не вигадувати). Дрейф-доки гірші за відсутні.
- **Граф wikilinks:** спершу зафіксуй список slug-ів у MoC, дай його всім агентам що пишуть ноти → лінки збігаються. Верифікація: скрипт, що звіряє всі `target` з наявними файлами (basename + відносний шлях).
- **Сабагенти** не тригерять `SessionStart`/`UserPromptSubmit` → у промпті явно кажи їм прочитати 2-3 зразкові ноти для тону + список валідних wikilink-цілей.

## Як масштабувати на нові ноти
Делегувати написання груп нот паралельним `executor`-агентам: кожному дати (а) 2-3 готові ноти як еталон тону, (б) повний список валідних wikilink-slug-ів, (в) точні `src`-файли для звірки. Я (оркестратор) пишу сам лише якірні файли: MoC, AGENTS.md, хуки, головну тех-ноту з унікальним знанням.

## Вартість
Token-intensive за дизайном (кожен запит фанаутить у vault + хуки реінжектять контекст). Рекомендований план: Claude Max 5×.

2. Скрипт цілісності wikilinks (0 broken).
3. `typecheck` + `build` зелені.
